# 语法优化与翻译功能拆分需求

## 1. 文档信息

- **项目**：AuralAI
- **版本**：V1
- **状态**：需求方案
- **范围**：仅拆分当前已有的语法优化和翻译职责
- **参考项目**：[pot-desktop](https://github.com/pot-app/pot-desktop)

## 2. 背景

当前 AuralAI 的语法优化流程同时包含翻译结果：

- `GrammarSettings` 的提示词同时要求翻译、语法检查和改写。
- `GrammarAIResponse` 同时保存 `translation`、`errors` 和 `options`。
- 语法历史记录同时保存翻译字段。
- 语法快捷键和选中文本流程共用同一个 AI 请求和结果浮层。

这使用户难以区分“帮我改好这句话”和“告诉我这句话是什么意思”，也使后续加入独立词典或普通翻译服务时需要修改语法功能。

## 3. V1 目标

将现有能力拆分为两个独立的产品功能和代码职责：

1. **语法优化**：继续负责 AI 语法检查和文本改写。
2. **翻译**：从语法优化结果中独立出来，继续提供当前已经存在的翻译能力。

本版本只做职责、入口、结果模型和历史记录的拆分，不改变翻译实现方式，不增加新的翻译服务。

## 4. 非目标

以下内容不属于 V1：

- 接入 ECDICT、macOS Dictionary Services 或其他词典服务。
- 移除 AI 翻译或改为非 AI 翻译。
- 新增单词音标、词性、例句或发音面板。
- 新增句子翻译 Provider。
- 新增 OCR、截图翻译或输入翻译。
- 改变现有快捷键默认值。
- 改造现有浮层视觉样式。
- 重构 Accessibility、剪贴板或 TTS 基础服务。

## 5. 功能定义

### 5.1 语法优化

语法优化继续面向正在编辑的文本：

- 支持当前输入框全文。
- 支持输入框内的选中文本。
- 使用现有 AI 请求配置。
- 返回语法问题和一个或多个改写建议。
- 用户选择建议后，可以替换原文。
- 继续使用现有语法快捷键、语法历史和语法结果浮层。

语法优化结果不再承担对外展示翻译的职责。

### 5.2 翻译

翻译作为独立入口保留当前已有的翻译行为：

- 主要输入为用户选中的文本。
- 使用当前项目已有的翻译请求能力，保证 V1 行为不变。
- 只展示翻译结果，不自动替换原文。
- 使用独立的翻译结果模型和翻译历史。
- 翻译操作的取消、失败和关闭不应影响语法优化状态。

V1 中“翻译”仍然可能使用现有 AI 服务，这是为了完成职责拆分；非 AI 查词属于后续版本。

## 6. 交互要求

### 6.1 入口

- 现有语法快捷键继续触发语法优化。
- 翻译使用独立入口，优先沿用当前已有的选中文本触发方式。
- 两个入口的快捷键配置和状态提示必须可以分别识别。
- 不修改现有朗读快捷键行为。

### 6.2 文本捕获

- 翻译入口只处理当前选中文本，不读取整个输入框作为翻译内容。
- 继续复用 `FocusedTextInputService` 和现有剪贴板 fallback。
- 选区为空时显示明确错误状态。
- 捕获失败时不得向 AI 发起请求。
- 翻译流程结束后继续恢复 Accessibility 轮询状态。

### 6.3 结果展示

- 语法结果继续显示错误和改写选项。
- 翻译结果只显示翻译内容及必要的原文信息。
- 翻译结果不得出现语法错误或语法改写选项。
- 翻译结果关闭、超时、失败时不得关闭或重置语法结果。
- V1 可以继续复用现有浮层的窗口定位逻辑，但结果视图和状态模型必须独立。

### 6.4 原文替换

- 语法优化保留当前的“选择建议后替换原文”行为。
- 翻译功能不提供原文替换操作。
- 翻译浮层中的复制操作（如当前已有）只复制翻译内容，不修改选区。

## 7. 数据和代码拆分要求

### 7.1 结果模型

将当前 `GrammarAIResponse` 拆分为职责明确的模型：

```swift
struct GrammarOptimizationResult {
    let errors: String?
    let options: [String]
}

struct TranslationResult {
    let originalText: String
    let translatedText: String
}
```

字段命名可以遵循现有代码风格，但语法模型不得继续依赖 `translation` 字段。

### 7.2 服务边界

建议保留当前服务结构，新增最小边界：

```text
GrammarAIService
TranslationService
```

- `GrammarAIService` 只负责语法优化请求和语法响应解析。
- `TranslationService` 只负责当前翻译请求和翻译响应解析。
- 两个服务不能互相调用。
- 不在 V1 中引入通用 Provider 框架或额外抽象层。

### 7.3 流程边界

`AuralAIApp.swift` 中的处理流程需要分开：

```text
语法快捷键
  -> 捕获输入框/选区
  -> GrammarAIService
  -> 语法结果浮层
  -> 替换原文

翻译入口
  -> 捕获选区
  -> TranslationService
  -> 翻译结果浮层
  -> 关闭或复制结果
```

可以共用选区捕获和窗口定位的底层代码，但不应共用请求任务、请求 ID、结果模型或取消回调。

### 7.4 历史记录

- 语法继续使用 `GrammarHistoryStore`。
- 翻译新增独立的翻译历史存储。
- 新的语法历史不再写入翻译字段。
- 不要求读取、保留或迁移旧版本语法历史。
- 升级到 V1 后，可以清空或忽略旧历史数据，并分别初始化新的语法历史和翻译历史。

## 8. 设置界面要求

将设置中的配置职责拆分为两个区域：

### 语法优化设置

- 语法快捷键
- AI API 地址、模型和 API Key
- 语法系统提示词
- 语法结果浮层配置
- 语法历史

### 翻译设置

- 翻译快捷键
- 当前翻译配置
- 翻译目标语言（沿用现有默认值）
- 翻译结果浮层配置
- 翻译历史

V1 不新增词典配置，也不新增非 AI 服务配置。

## 9. 兼容性要求

- 现有语法快捷键行为保持不变。
- 现有语法结果选择和替换行为保持不变。
- 现有朗读功能保持不变。
- 已保存的 AI 配置继续有效。
- 旧版本语法历史不要求兼容，升级后可以从空历史开始。
- Accessibility 权限检查、剪贴板 fallback 和应用激活流程不改变。
- 翻译请求失败只影响翻译流程，不得取消正在进行的语法请求。

## 10. 测试要求

### 单元测试

- 翻译响应可以独立解析为 `TranslationResult`。
- 语法响应解析不再要求存在 `translation` 字段。
- 翻译和语法历史分别保存、加载、删除和清空。
- 存在旧格式历史数据时，应用可以安全忽略或清空数据，不得因此崩溃。
- 两种请求的取消不会互相影响。

### UI 测试

- 语法入口仍显示语法结果和改写选项。
- 翻译入口只显示翻译结果。
- 翻译结果中不存在语法错误和改写按钮。
- 语法结果中不存在翻译专属控件。
- 两个功能可以分别关闭浮层。

### 手动验证

- 在 TextEdit、Safari、Chrome 或 VS Code 中测试选区捕获。
- 测试没有选区、Accessibility 权限不足和剪贴板无变化的情况。
- 在语法请求进行时触发翻译，确认两者互不取消。
- 确认翻译操作不会替换选中文本。

## 11. 验收标准

V1 满足以下条件即可验收：

1. 用户能明确区分语法优化和翻译两个入口。
2. 语法优化仍可完成现有的 AI 检查、改写和替换流程。
3. 翻译可以独立发起、展示和关闭。
4. 翻译结果不再通过 `GrammarAIResponse.translation` 传递。
5. 语法历史和翻译历史不再混用。
6. 翻译失败不会影响语法优化，反之亦然。
7. 本版本没有引入词典、音标、短语翻译或其他新功能。
8. 旧版本历史无需迁移，升级后可以从空历史开始。

## 12. 后续版本方向

以下内容在 V1 完成后另行评估：

- 本地 ECDICT 单词查词。
- macOS Dictionary Services。
- 非 AI 的句子翻译服务。
- 单词发音、词性、例句和词形还原。
- 统一的翻译 Provider 配置。
